# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

PAX is a Rust project for discovering, declaring, managing, and reproducibly acquiring academic papers, using Nix as the artifact backend. The design principle: **PAX understands papers, Nix understands artifacts.**

- PAX handles: academic search, metadata resolution, source resolution, paper declarations, local organization, bibliography export.
- Nix handles: fetching, hashing, verification, caching, storage, garbage collection.

Intended workflow: `Search → Select → Declare → Fetch → Manage → Reproduce` (see [`mvp.md` at tag `1.0.0`](https://github.com/pax-project/pax-core/blob/1.0.0/docs/mvp.md) for the original command surface and design philosophy — its full §4 command surface is built; ongoing work is tracked in this repo's Issues, see "Known gaps" below).

**This repository's primary artifact is `pax-core`, a library — not a CLI tool that happens to have a core module.** The `pax` binary (`src/bin/pax/main.rs`) is a thin, optional client of that library, gated behind the `cli` Cargo feature; [`lazypax`](https://github.com/pax-project/lazy-pax) is a separate repo that's just another client of the same library — README.md itself doesn't mention it, since lazy-pax depends on pax-core and not the other way around. [`mvp.md`](https://github.com/pax-project/pax-core/blob/1.0.0/docs/mvp.md) is the original, pre-implementation spec for the full command surface — don't assume a command or flag exists just because it's documented there. **Planned and in-progress work is tracked in this repo's [Issues](https://github.com/pax-project/pax-core/issues) and the org's [pax Project](https://github.com/orgs/pax-project/projects/2)** — check them before assuming something is done or not done. `mvp.md` and the 1.0.0-era `status.md` survive only at tag `1.0.0` — see "Known gaps" below.

## Environment

The project uses Nix + direnv for the dev shell (`flake.nix`, `.envrc`). `.envrc` does `use flake`, so `direnv allow` sets up a shell with cargo/rustc/rustfmt/clippy/rust-analyzer and the OpenSSL env vars (`PKG_CONFIG_PATH`, `OPENSSL_DIR`) needed to build the native TLS dependencies.

Secrets/config load via `dotenvy` from `.env` at startup, but only in the `pax` binary (`dotenvy::dotenv().ok()` in `src/bin/pax/main.rs`'s `main()`) — the library itself never reads the environment directly; it's passed a `pax_core::Config` instead. Recognized vars: `SEMANTIC_SCHOLAR_API_KEY` (Semantic Scholar falls back to unauthenticated requests if unset) and `ARXIV_CONTACT` (arXiv's contact-email etiquette header, omitted if unset).

## Commands

```bash
cargo build                        # builds the library + the pax binary (cli is a default feature)
cargo build --no-default-features  # builds pax-core alone — proves the CLI deps (clap, dotenvy, tokio's runtime) aren't pulled in
cargo run --bin pax -- <args>      # e.g. cargo run --bin pax -- search "actor model"
cargo test                         # unit tests (library.rs round-trip, provider CandidateId parsing)
cargo test <substring>             # run a single test, e.g. cargo test candidate_id_rejects_bare_doi
cargo fmt                          # format (rustfmt is in the flake devshell)
cargo clippy                       # lint
```

## Architecture

```
src/
  lib.rs          # pax-core's public API: re-exports + search_all()
  citations.rs    # references()/cited_by()/related() (+ *_many for several seeds): resolve a seed per provider, page its citation (or related-works) lists; incomplete_lists(): why a list is partial
  provider/       # Provider trait, ProviderId, CandidateId, CandidateWork, ProviderError
    mod.rs        #   + the five provider implementations, one file each (dblp.rs: search + lookup only); collect_pages() drives paging
    filter.rs     # Filters (year/type/language) and AppliedFilter: how each provider applied each one
    pacing.rs     # Pacer (pure, takes `now`) + Paced (locked, sleeps): minimum interval between a provider's requests
  paper.rs        # Paper, Identity, Artifact (+ is_local), Local (+ alias), PaperRef (citation key), is_valid_alias
  library.rs      # Library::load()/save() against research/papers.nix
  library_index.rs # LibraryIndex: is a result declared or excluded, matched by DOI/arXiv identity key
  identity.rs     # IdentityKey (DOI → arXiv id → title+year) + group(): which records are the same paper
  merge.rs        # merge_works/merge_pages: duplicates collapsed into MergedWork, with before/after/unmatched counts
  output.rs       # serializable result shapes (one per command): what `pax --json` prints and other clients can return
  names.rs        # library names: lookup() (citation key, then alias, in both files), declared_key(), holder()/check_alias() for the one namespace
  exclusions.rs   # Exclusions::load()/save() against research/excluded.nix; exclusion_key()
  search_log.rs   # research/search-log.jsonl: one JSON line per provider per search; *_logged() variants;
                  #   SearchOptions::label is stored on each line (log metadata only, never sent to providers);
                  #   add_candidate_logged(): add_candidate + one `manual` line (reference, label, the record's keys)
  stats.rs        # stats(): PRISMA 2020 flow-diagram counts from the search log, excluded.nix and papers.nix (related works in their own Identified bucket,
                  #   `manual` lines in Identified::other_sources keyed by label);
                  #   decisions (declared/excluded) are matched to logged records by identity::group for awaiting_screening;
                  #   by_label: per-label identified/distinct/new/duplicates, labels in first-appearance order
  nix_attrs.rs    # the attrset subset both files use: tokenizer, parser, field writers, atomic write
  nix.rs          # init_library(): scaffolds research/flake.nix + research/papers.nix from templates/;
                  #   every `nix` call: prefetch_file, build_package, hash_file/add_file/local_artifact_path (fetch --file)
  citation_key.rs # generates a citation key for a newly declared paper (surname+year, disambiguated)
  bibtex.rs       # renders declared papers as BibTeX (bibtex::render)
  github.rs       # publish_to_github_release: shells out to `gh` to publish a local PDF as a release asset
  process.rs      # shared subprocess-with-timeout helper for anything shelling out (nix, gh)
  error.rs        # PaxError, unifying ProviderError + io/parse errors
  bin/
    pax/
      main.rs     # clap CLI — argument parsing, dispatch, output formatting only
      sink.rs     # Sink: one method per command result; TextSink (people) and JsonSink (`--json`)
      exit.rs     # exit codes, and the one place errors map to them
```

**Reference types — the load-bearing design decision in this codebase:** `add`/`show` and `search` operate on fundamentally different address spaces, so they use different types:
- **`CandidateId`** (`provider/mod.rs`) — a fully-qualified `provider:native_id` reference (e.g. `openalex:W2741809807`, `arxiv:2301.01234`) to a single, unresolved search hit. Its `FromStr` impl is deliberately strict: it rejects a bare DOI, a title, or free text (see `provider::tests` for the exact rejected/accepted cases). This makes "search returned two results, which one did you mean?" structurally impossible at the `add`/`show` argument boundary — disambiguation is `search`'s job (it already returns a list); `add`/`show` only ever accept a reference that is already unambiguous.
- **`PaperRef`** (`paper.rs`) — a citation key (e.g. `turing1936`) addressing the closed set of papers already declared in the local library. Used by `remove`/`edit`/`fetch`/`open`, which also accept the paper's alias (see **Aliases** below; `sync` operates on the whole library rather than a single `PaperRef`, but reuses `fetch_paper` per key internally — see #7).

**`Provider` trait** (`provider/mod.rs`) — `fn id()`, `async fn search(query)`, `async fn get(native_id)`. One implementation per provider module (`openalex.rs`, `crossref.rs`, `semantic_scholar.rs`, `arxiv.rs`, `dblp.rs`), each also providing `From<ProviderNativeType> for CandidateWork`. `get()` is implemented for all five today (`OpenAlexClient::get_work`, Crossref `/works/{doi}`, `SemanticScholar::get_paper`, arXiv `fetch_page` by id, dblp `/rec/<key>.xml`). Crossref is the exception to "one crate per provider": the `crossref` crate builds URLs and supplies the HTTP client, but `crossref.rs` parses responses into its own lenient types, because the crate's `Work` requires fields (e.g. `title`) that real records omit. dblp has no client crate: `dblp.rs` calls the search API (`/search/publ/api`, JSON, into lenient types: a repeatable field is one value or a list) with `reqwest`, and parses the `/rec/<key>.xml` export with `quick-xml` (already in the tree through `arxiv-tools`); a dblp id is the dblp key (`dblp:conf/icse/Smith20`). It applies a year range of up to 30 years server-side (`year:` terms ORed with `|`), longer ranges and mapped types after retrieval, language not at all; an HTML answer (its bot check) is reported as such. dblp has no abstracts and no citation graph, so it isn't in `CITATION_PROVIDERS`; a `dblp:` seed is fetched for its DOI like any other. Abstracts: OpenAlex (no `select` on list requests), Crossref (JATS markup stripped to plain text by `crossref::plain_abstract`) and arXiv always fill `CandidateWork.abstract_text`; Semantic Scholar's search and citation lists only ask for `abstract` when `SearchOptions::abstracts` is set (`list_fields`), while its `get` always does. A merged row's abstract is `MergedWork::abstract_text`: the first non-empty one in `merge::MERGE_ORDER` (a slice of every provider; the fixed-size `PROVIDER_ORDER` is deprecated, since it couldn't grow to include dblp).

**`pax::search_all(query)`** fans out to the providers `SearchOptions::search_providers()` names concurrently-in-sequence (awaited one after another, not via `join!`) and returns `HashMap<ProviderId, Result<Vec<CandidateWork>, ProviderError>>` — a failing provider doesn't fail the whole search, and the *caller* (the CLI) decides how to display an error, since the library itself never prints. By default that's `DEFAULT_SEARCH_PROVIDERS` (OpenAlex, Crossref, Semantic Scholar, arXiv); dblp, which covers computer science only, is asked only when named in `SearchOptions::providers` (CLI: `search --provider`, repeatable).

**Citation graph** (`citations.rs`) — `references(seed, …)` / `cited_by(seed, …)` return the same per-provider `HashMap<ProviderId, Result<SearchPage, CitationError>>` shape as `search_all_paged`, for OpenAlex and Semantic Scholar only (`CITATION_PROVIDERS`). The seed accepts both address spaces: a `CandidateId` from any provider, or a `PaperRef` citation key (told apart by the colon, as in `show_reference`). `SeedIds` resolves it to each provider's lookup key — its own id if the seed came from it, else `doi:`/`DOI:` (a `CandidateId` seed is fetched from its own provider to learn the DOI), else the arXiv id (from an arXiv seed, an arXiv DOI, or a library paper's arxiv.org `source_url`) — and a provider it can't be resolved in or found in gets a `CitationError` while the other still answers. The lists are the provider-level `OpenAlexProvider::references_page`/`citations_page` (`cited_by:`/`cites:` work filters, so search filters apply server-side) and `SemanticScholarProvider::references_page`/`citations_page`. The latter fetch the list endpoints with their own `reqwest` client and lenient types rather than the `semantic_scholar` crate, whose `Paper` requires a `paperId` that unmatched references lack; their total is the seed's `referenceCount`/`citationCount`, and year/type filters run after retrieval. The library returns the lists per provider; the CLI prints each provider's count, then merges them with `merge_pages` (generic over the error type, so it takes `CitationResults` as well as search results), like `search`. Why a list is incomplete is typed and computed once, in the library: `CitationError::reason()` / `incomplete_reason()` / `incomplete_lists()` give an `IncompleteReason` — `withheld` (`ProviderError::Withheld`, Semantic Scholar's `data: null`), `failed`, `unresolved` (`Unresolvable`/`SeedNotFound`) or `truncated` (`!page.is_complete()`). The CLI prints it beside each count and exits 3 (`exit::citations`) for any but `truncated`; the `*_logged` functions record it as the log line's `reason` (the generic `log_results` can't tell an error's kind, so it records none). **Several seeds:** `references_many`/`cited_by_many` (and `*_many_logged`) return `SeedResults`, one `SeedResult` per seed in order; seeds are looked up sequentially, an invalid seed fails only itself (`results: Err`), and a seed that's the same paper as an earlier one (`SeedIds::same_paper`: a shared provider id, DOI or arXiv id, or the same string) gets `same_as` and a copy of its lists rather than a second fetch. `SeedResults::merge()` feeds every seed's pages through `merge::merge_indexed` (the positions behind `merge_works`) to attribute each merged record to a `RecordSource { seed, provider }`. Logging writes each seed's lines exactly as a single-seed run would (so `pax stats` is the same either way) in one append; `append_to_library` stamps every line of one command with one `run` id. The single-seed functions are unchanged. **Pacing:** every Semantic Scholar request (each `semantic_scholar` crate `send()`, though not that crate's own internal retries, and each `get_json` attempt) first waits on one process-wide `PACER` (`provider/pacing.rs`), at least `SemanticScholarProvider::DEFAULT_MIN_INTERVAL` (1s) after the previous one, or `with_min_interval`'s value. It's a `static`, not a field, because `lists_for` builds a fresh provider per seed and the rate limit is per caller; `Config` can't carry the interval since it isn't `#[non_exhaustive]`. A 429/5xx's `Retry-After` (or backoff) is `PACER.hold_off`, so it holds back every request, not just the retry. The CLI notes the expected wait on stderr (`pacing_note`) when it's 10s or more. **Related works:** `related`/`related_many` (and `*_logged`, logged as `SearchCommand::Related`) are a third `Direction` through the same `SeedIds` resolution, `CitationResults`/`SeedResults` shape, merge and attribution: `OpenAlexProvider::related_page` (the work's `related_works`, fetched with one `openalex_id:` OR-filter so search filters apply server-side, at most 100 ids) and `SemanticScholarProvider::recommendations_page` (`/recommendations/v1/papers/forpaper/{id}`, `from=recent`, up to 500, year/type after retrieval). Neither reports a total, so every related page has `total: None` and `incomplete_reason` is `truncated` for any list returned — never complete; only an error means a list is missing. Each seed is asked separately (not Semantic Scholar's multi-paper POST), so every record is attributable to one seed. `stats` counts `related` lines in their own `Identified::related_works` bucket, not with citation searching (both are PRISMA "other methods"; recommendations aren't citation edges).

**Manual adds** (`pax add <ref> --label <source>`) — `add_candidate_logged` runs the same declare path as `add_candidate` (both go through the crate-private `declare_candidate`, which also returns the resolved `CandidateWork`) and appends one `SearchCommand::Manual` line (`manual_log_entry`: `reference` = the `CandidateId`, `provider` = its provider, `label`, one record's identity keys). Nothing is logged without a label, or when the add is refused or fails. `stats` counts `manual` lines in `Identified::other_sources`, keyed by label rather than provider (each label is its own PRISMA "other methods" source), so a seed paper the reviewer already knew matches a logged record instead of landing in `decided_outside_log`, and a seeds-only review balances. They join `by_label` and review-wide duplicate counting like any other line.

**`Library`** (`library.rs`) — `research/papers.nix` is Nix syntax, but it's a schema PAX itself invented and fully controls (a flat attrset of `citation_key = { ...fields... };` records; `research/flake.nix` only ever reads `source_url`/`hash` off each entry generically via `builtins.mapAttrs`, so extra fields are harmless to it). `Library::load`/`save` are a small hand-rolled tokenizer/parser and writer scoped to exactly that fixed shape — deliberately not a general Nix-language parser (no `rnix-parser` or similar dependency). `research/papers.nix` is the single source of truth; nothing else shadows it. `add`/`edit`/`remove` all mutate a `Library` today; round-trip correctness is proven by a unit test in `library.rs`. The tokenizer/parser and writers themselves live in `nix_attrs.rs`, shared with `excluded.nix`; `library.rs` only maps entries to `Paper`s.

**`Exclusions`** (`exclusions.rs`) — `research/excluded.nix` is the library's blacklist: papers screened and decided against, keyed by normalized DOI (or `provider:id` for a work without one, see `exclusion_key`), each with a `title`, an optional `year`, a required `reason`, a `stage` (`screening` / `full-text`, the two PRISMA exclusion boxes), and an optional free-text `criterion` and `round` (written only when set; `exclude_paper_with` + `ExclusionOptions` record them, `exclude_paper` keeps its 2.0 signature; `stats` groups both stages by criterion). Deliberately a separate file: `papers.nix` and the flake are untouched, and a missing file means no exclusions. `exclude_paper` (`pax exclude`) refuses a paper already in `papers.nix`, and `add_candidate` refuses one in `excluded.nix` (`PaxError::AlreadyExcluded`), matched by the same keys `LibraryIndex::is_excluded` uses (`library_index::find_exclusion`), before and after resolving. `unexclude_paper` (`pax unexclude`) is the only way back: it removes one entry, found by exclusion key, alias, DOI or provider reference.

**`LibraryIndex`** (`library_index.rs`) — how callers flag results `[in library]` / `[excluded]`: built once per command from `papers.nix` + `excluded.nix`, it matches a result by any of its DOI or version-less arXiv keys (`identity::work_id_keys`), since a paper, not a version, is the unit; a merged row is flagged if any of its records is. Title+year keys aren't used. It supersedes the deprecated `known_dois` / `excluded_keys`, which matched one exact DOI or key.

**Aliases** (`names.rs`) — an optional, user-chosen `alias` (e.g. `P17`, `[A-Za-z0-9_.-]+`, `paper::is_valid_alias`) on a declared paper (`Local::alias`) or an excluded one (`Exclusion::alias`), written as `alias = "...";` only when set. Citation keys and aliases in both files are one namespace (`names::holder`): `edit_paper` (`PaperEdits::alias`, `""` clears) and `exclude_paper_with` (`ExclusionOptions::with_alias`; `None` keeps an earlier exclusion's alias, `""` clears) refuse a name another paper holds with `PaxError::NameTaken`, `edit --rename` too, and `add_candidate` disambiguates its generated key against aliases. Every library-name lookup goes through `names::lookup` (citation key, then declared alias, then excluded alias): `remove`/`edit`/`fetch`/`open` via `names::declared_key` (an excluded alias is `PaxError::ExcludedNotDeclared`), `show_reference` (`ShowResult::Excluded`), citation seeds (an excluded alias resolves through its exclusion key) and `unexclude_paper`. `remove_paper_entry` returns the removed paper so the CLI can print the freed alias, and `edit_paper_entry` the edited one (under its new key after a rename) for `edit --json`. `Local` and `PaperEdits` are `#[non_exhaustive]` with `new()` + `with_*` constructors.

**JSON output** (`output.rs`, `pax --json`) — every command's result has one serializable shape in `pax_core::output` (`PaperList`, `Shown`, `SearchResults`, `DoiRecords`, `CitationResults`, `Added`, `DeclaredPaper`, `Excluded`, `Exported`, `FetchResult`, `SyncResults`, `CheckResults`, `Opened`, `Initialized`; `stats` prints `Stats` itself, unchanged). They're built from the library's own results (`new` / `From`), never field by field, and are all `#[non_exhaustive]`, so fields can be added in a minor release; the `schemars` feature derives `JsonSchema` on them and on `Stats`, for pax-ai's MCP server to return the same shapes. The CLI's `--json` is a clap `global` flag (so `stats --json` still works) that picks `JsonSink` over `TextSink`; the `Sink` trait has one method per command result, the text rendering lives in `TextSink`, and exit codes are computed in `main.rs` apart from printing, so they're the same either way. `JsonSink` prints one pretty document on stdout and writes stderr as one compact JSON object per line (`{"error": {"code", "message"}}` for the failure, through `Sink::failure`; `{"warning": …}` otherwise); clap's own errors are turned into the error object in `main()` when `--json` is among the arguments.

**`pax init`** (`nix.rs::init_library`) materializes `research/flake.nix` + an empty `research/papers.nix` from embedded templates (`include_str!` from `templates/flake.nix.template` / `templates/papers.nix.template`). The `research/` directory is gitignored; the top-level `research/flake.nix` / `research/papers.nix` checked into *this* repo are a working example of that generated structure, not the templates themselves.

**Local artifacts** (`fetch_file`, `pax fetch <key> --file <path>`) — a PDF the user already has (paywalled, no reachable URL): `nix hash file` gives its flat SRI hash, `nix store add-file --name <key>` stores it at the same path a fixed-output derivation with that name and hash has, and the hash is recorded in `papers.nix`. There is deliberately no new `Artifact` field (`Artifact` isn't `#[non_exhaustive]`; one would be a major release): a local artifact is just `hash` set and `source_url` null (`Artifact::is_local`). A recorded hash the file doesn't match is `PaxError::HashMismatch` unless `force`. Nothing can refetch one, so `fetch_paper`, `check_artifacts`/`check_library` and `resolve_artifact_path` look it up in the local store (`nix-store --print-fixed-path` + `nix path-info`, `nix::local_artifact_path`) and report `PaxError::LocalArtifactMissing` when it's absent; the CLI maps that to exit 8, and `check`/`sync` exit 8 only when every problem is one. `resolve_artifact_path` never builds a local artifact through the flake, because a `research/flake.nix` from before this feature passes it to `fetchurl` with a null URL, which fails to evaluate; the current template sends it to `requireFile` (meta cleared, since `requireFile` marks itself unfree), whose failure message says to `fetch --file` again. Existing libraries keep their old flake: `nix::flake_builds_local_artifacts` (does it mention `requireFile`) drives the CLI's warning after `fetch --file`. `check_library`'s `CheckReport`/`CheckStatus` are exhaustive, so the typed error rides on the new `#[non_exhaustive]` `ArtifactCheck` from `check_artifacts`. `stats` counts any paper with a `hash` as included. The store path has no GC root: a garbage collection removes it like any other unreferenced path.

**A real user's research library is expected to be its own git repo** (`mvp.md` §6: `git clone <research-library>; cd <research-library>; nix build`), and Nix flakes only evaluate files that are tracked by git — an untracked `flake.nix` fails outright with "not tracked by Git" (confirmed: this is stock Nix behavior, not a PAX bug). So in a library that's already a git repo, `research/flake.nix`/`research/papers.nix` need at least `git add` (staged, not necessarily committed) before `pax open`/any other command that calls `nix build` will work — see #7's reproducibility-proof section for how this was found.
